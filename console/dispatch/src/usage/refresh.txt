Ask the dispatcher to refresh one of the factory's own pull requests that
conflicts with the branch.

Deterministic, no model, no container. Nothing runs it on a timer: what
schedules the factory's refreshes runs it for each pull request it wants
refreshed.

It reads pull request N of TEHAS_REPO now. It keeps it when it is open and
the bot's, closes exactly one open issue carrying tehas:awaiting-merge or,
after a handoff, needs-human-attention, and not tehas:running, not the
control issue, and is the only open pull request that closes it; and its
branch is in the repository. A draft is kept too
(console/dispatch/src/decide/retry.rs). A kept one that GitHub says is
CONFLICTING or UNKNOWN gets a request,
$TEHAS_HOME/state/refresh/<issue>.json:
{at, pr, head_sha, base_sha, asked}, asked being "pr". A request for the
same pull request at the same head keeps its time. No other request is
read, written or removed. Its line in logs/refresh.log is "asked for pull
request #N: wrote the request of #M" or "asked for pull request #N: not
refreshed: <why>".

It decides only that a pull request may need a refresh. Whether a refresh
starts is the dispatcher's, which checks each request again at the start
and drops one whose pull request no longer qualifies.

Usage:
  tehasbot refresh --pr N      ask for the refresh of pull request N now
  tehasbot refresh -h|--help   print this text and exit 0

Exit: 0 the request was written; 3 N is not a pull request the factory
refreshes, or it does not conflict: why is on stderr, nothing is written;
64 no --pr N, or an argument this command does not know; 78 instance
settings are missing or malformed; 1 the call to GitHub failed or its
answer could not be read, or the request could not be written.
