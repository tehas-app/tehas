Find the factory's own pull requests that conflict with the branch, and ask
the dispatcher to refresh them.

Deterministic, no model, no container. tehas-refresh.timer starts
tehas-refresh.service every minute, and a run goes ahead only when the last
one began TEHAS_REFRESH_EVERY minutes ago or more: the time it began is in
$TEHAS_HOME/state/refresh/last-run, in seconds. A run that fails counts, so
a GitHub that does not answer is asked again only after the interval. With
TEHAS_REFRESH_CONFLICTS other than 1, or inside the interval, it exits 0 at
once and calls nothing.

It lists the open pull requests of TEHAS_REPO and keeps the bot's that close
exactly one open issue carrying tehas:awaiting-merge or, after a handoff,
needs-human-attention, and not tehas:running, not the control issue, and are
the only open pull request that closes it; and whose branch is in the
repository. A draft is kept as any other (console/dispatch/src/decide/retry.rs). Of
those, the ones GitHub says are CONFLICTING get a request,
$TEHAS_HOME/state/refresh/<issue>.json:
{at, pr, head_sha, base_sha}. A request for the same pull request at the
same head keeps its time. UNKNOWN is skipped this run, and a request it has
stays: GitHub computes the state lazily and the next run reads it again. Any
other request is removed. One line per run goes to logs/refresh.log: how
many open pull requests it read, and of those how many conflict, how many
are still UNKNOWN and how many are not ours to refresh (another account's, a
fork, one the rule rejects, or one whose head or base is no sha), and how
many requests it wrote. The rest of the read are the bot's that do not
conflict.

With --pr N it reads that one pull request now, whatever
TEHAS_REFRESH_CONFLICTS and TEHAS_REFRESH_EVERY say, and applies the same
rule. A CONFLICTING or UNKNOWN one gets its request, with a last field
"asked": "pr". It does not read or write last-run and removes no request.
Its line in logs/refresh.log is "asked for pull request #N: wrote the
request of #M" or "asked for pull request #N: not refreshed: <why>".
With --json it also prints one object on standard output for exit 0, 3 and
1: {"asked", "pr", "issue", "head_sha", "why"}. asked is true when the
request was written, and why is then null; otherwise why is the reason, the
same words as on stderr. issue and head_sha are null when GitHub did not
name them.

It decides only that a pull request conflicts. Whether a refresh starts is
the dispatcher's, which checks each request again at the start. With
TEHAS_REFRESH_CONFLICTS other than 1 the dispatcher also drops, at each
poll, a request this run wrote before once its issue or pull request fails
one of those checks, as when either was closed.

Usage:
  tehasbot refresh             one run
  tehasbot refresh --pr N      ask for the refresh of pull request N now
  tehasbot refresh --pr N --json
                               the same, and print what it asked as JSON
  tehasbot refresh -h|--help   print this text and exit 0

Exit: 0 the run ended, or the setting is off, or the --pr request was
written; 3 --pr N is not a pull request the factory refreshes, or it does
not conflict: why is on stderr, nothing is written; 64 an argument this
command does not know; 78 instance settings are missing or malformed; 1 a
call to GitHub failed or its answer could not be read: no request was
written or removed.
