tehas setup: write this host's instance and start the factory, once.

Asks for what it is not given, when there is a terminal to ask on:

  --repo <owner/name>        the product repository
  --labellers "<a> <b>"      the logins whose labels count; never the bot
  --new-app                  make the GitHub App the factory acts as, in the
                             browser: setup prints one link, and you paste
                             back the address GitHub opens after you create
                             the app, or the code in it
  --app-owner <login>        the organisation or user that owns the new app
                             (the repository's owner)
  --app-name <name>          the new app's name (<repository>-factory)
  --app-id <id>              a GitHub App you have, in place of --new-app:
  --app-key-file <file>      its ID and its private key. Both or neither
  --endpoint <url>           the model endpoint, OpenAI-compatible, with its
                             /v1: its models are read from <url>/models
  --model <id>               the model to use; needed when the endpoint
                             offers more than one and there is no terminal
  --model-key-file <file>|-  the endpoint's key, if it takes one
  --provider <name>          the provider's name in models.json (main)
  --control-issue <n>        the control issue; without it one is made
  --no-build                 leave out the sandbox image and the gates
  --force                    replace a setting that is there and differs

--token-file is refused: the factory acts as a GitHub App.
--app-installation is ignored: the installation is looked up.

Then, in this order, stopping at the first step that fails:
  1. checks the endpoint offers the model. With --new-app it makes the app:
     the app's key goes to ~/.config/tehas/github-app.pem, mode 600, and
     TEHAS_GITHUB_APP_ID to instance.env at once, then it waits up to 10
     minutes for the app to be installed. It checks the app is installed on
     the repository and may write its contents, issues and pull requests,
     names any other repository the instance names that the app does not
     reach, and makes the control issue
  2. writes ~/.config/tehas (or the directory instance-dir names):
     instance.env with the required settings and TEHAS_GITHUB_APP_ID,
     models.json, the app's key in ~/.config/tehas/github-app.pem and the
     model key in env, mode 600, and the app's login in
     ~/tehas/state/github/login. The later steps run gh through
     ~/tehas/shim/gh
  3. gives git the bot's name and noreply address, unless it has one; git's
     helper for github.com is the app's gh
  4. clones the product to ~/tehas/repos/<name>; a first run installs
     first. A checkout that is there is fetched and fast-forwarded on its
     branch; one with local work, or a fetch that fails, is left as it is and
     named, and the run goes on
  5. runs install.sh beside this command, then tehas labels
  6. builds the sandbox image unless it is there, and runs the product's
     gates in it with tehas check-product --sandbox where that is installed
  7. enables the dispatch timer and path, starts the docs server, runs
     tehasbot github-token --check and prints the dashboard's address

A second run changes nothing that is right, and a second --new-app on an
instance that names an app checks that app and makes none. A setting that
is there and differs is never replaced without --force: the run stops with
78 before it calls anything or writes anything. Steps 1 and 2 are the
console's, and what it says goes to standard error.

Usage:
  tehas setup [options]

Exit: 0 done; 1 a check or a step failed (a step's own status when it has
one); 64 an unknown option, --app-id or --app-key-file alone or with
--new-app, or --app-owner or --app-name without it; 78 a setting is missing,
malformed, or differs from the one there without --force, --token-file, a
pasted address without this run's state, a key with no app ID (or an app ID
with no key) for --new-app, a git config file git could not open, or there is
no console and no checkout to build it from.
