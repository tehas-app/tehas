tehas init-product: propose the contract files the product is missing, as a
pull request opened by the bot.

Usage:
  tehas init-product             write the missing files on a branch, push it
                                 and open a pull request
  tehas init-product --dry-run   print the files it would write, change nothing

What it writes, only where the default branch has no such file:
  AGENTS.md             a short template for a person to fill in
  .pi/verify-cmd        the gate, guessed from the product's stack
  .pi/worktree-setup    the install step, guessed the same way, when there is one

The stack is guessed from the default branch's Makefile (a test or check
target), package.json, Cargo.toml, go.mod, pyproject.toml, or else the run
steps of its CI workflows. Every guessed file says in a comment that a person
should check it. With no guess, .pi/verify-cmd holds only that comment, and
tehas check-product still fails on it.

The work happens in a fresh clone under $TEHAS_HOME/tmp, removed afterwards.
The branch is tehas/init-product; it never commits to the default branch.
The push uses gh's credentials.

Exit: 0 the pull request is open, or nothing is missing; 1 git or gh failed,
or the branch is already on origin; 64 a wrong argument; 78 the instance
settings are missing or malformed, or the checkout is not a clone of
TEHAS_REPO.

Instance settings (lib/config.sh): TEHAS_REPO, required; TEHAS_WORK_REPO,
derived; TEHAS_BRANCH, optional.
