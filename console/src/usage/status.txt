Print the state of the factory: is it taking work, what is in the queue and
what the current or last cycle is doing.

It reads $TEHAS_HOME/live/health.json, which the dispatcher refreshes at
every poll and at the end of every cycle, and the poll line from the state
store. No network, no model, no instance settings, and it writes nothing. What it prints is as old
as that file, and the first line says how old. The slice line is what the
dispatcher's last poll read of tehas.slice, with that poll's own age.

A stopped dispatcher cannot report itself: the file just stops changing. So
a file older than ten minutes is not believed, whatever it says: the first
line then reads "stale" and the exit status is 1.

The lines are the console's (console/src/status.rs), which `tehas top` uses
for its frame.

Usage: tehas status [--json]

  factory   pass: Idle, taking work. (40 s ago)
  poll      last 24 s wall, 3.1 s CPU, 12 gh (0 writes); last hour 14 polls, 41 s CPU, 2 writes
  queue     2 in line, 0 building, 1 in review, 0 stopped (40 s ago)
  cycle     #12 handoff at step review, 3 min ago
  plan      #7 turn 2 running, started 12 min ago
  slice     room for 2 cycles (4 GiB of 20 GiB promised, reserve 2g, 40 s ago)
  platform  cb6912a, 19 commits behind origin/main since 2026-10-13, fetched 20 min ago

A plan line is there for each planning turn in flight. The slice line reads
"holding: ..." when the last poll held cycles back, and "unknown: no poll
has reported in 10 min" when no poll got as far as reading the slice in that
time, as while the factory is paused. The platform line is there only on a
host with a platform checkout, the poll line only with a poll on record.

With --json the same facts as one object on standard output, for a program
(host/docs/api.md has every field):
  {"api": 1, "time": "...", "age": 40, "stale": false, "state": "pass",
   "reasons": [], "paused": {"local": false, "label": false},
   "allHands": false, "limit": {"state": "none"},
   "running": [{"issue": 12, "since": "...", "step": "review"}],
   "planning": [{"issue": 7, "turn": 2, "since": "..."}],
   "demand": {"waiting": 2, "oldestWait": 5400},
   "hold": {"why": "count", "text": "holding: ..."},
   "room": {"cycles": 0, "maxAwaiting": 3, "slice": 2}}
Without a health file it prints nothing on standard output.

Exit: 0 the factory is taking work or is paused (pass, warn); 1 it is not
(fail), the file is older than ten minutes, or there is no health file yet;
64 an argument other than --json.
