tehas history: the cycles and planning turns that ended, oldest first, for a
program to read.

One line per end: the history on the state store (history-show), which
tehasbot cycle writes when a cycle ends and the dispatcher when a planning
turn ends (plan-end). tehas history reads both kinds, puts the lines in the
order they were written, which is the order they ended, and prints the ones
after a cursor. It reads only: no network, no
lock a cycle holds, and nothing under $TEHAS_HOME is written but what SQLite
keeps beside the store as it reads. A line it
cannot read is left out, not an error; a store that cannot be read is an
error, and nothing is printed: never a listing with the cycles missing.

Usage: tehas history [--json] [--after CURSOR] [--issue N]

  --after CURSOR   what this command printed as "next" before: only the lines
                   written after it, as 1760700000-12-41. The shape of v0.13
                   and before, 1760700000-12, is still read. A cursor the
                   shape of none this command could have printed is a bad argument,
                   which reads nothing: a mangled cursor does not become an
                   empty listing the caller would keep
  --issue N        one issue's lines; N is a number that does not start with
                   a zero and is at most nine digits

Without --json, one line each, oldest first:

  1760700000-12-41  work  #12  handoff  rc 10  step review  parked  repeat 1  pr https://github.com/...
  1760700300-7-42   plan  #7   finished  turn 3

`repeat <n>` names the n parks in a row that stopped exactly as this one did,
it not counted, and is on the park of a run only: see the manual.

With --json, one object on standard output and nothing else:

  {"api": 1, "cycles": [
     {"cursor": "1760700000-12-41", "kind": "work", "issue": 12,
      "started": "2026-10-17T11:20:00Z", "ended": "2026-10-17T13:20:00Z",
      "status": 0, "outcome": "handoff", "pr": "https://github.com/...",
      "step": "review", "cap": "awaiting-human-merge", "parkReason": "merge",
      "failureKind": "review", "failureCause": "...", "provider": false,
      "parked": true, "repeat": 1, "by": "alice", "how": "label"},
     {"cursor": "1760700300-7-42", "kind": "plan", "issue": 7,
      "started": "2026-10-17T13:20:00Z", "ended": "2026-10-17T13:25:00Z",
      "status": 0, "outcome": "finished", "turn": 3, "by": "alice",
      "label": "tehas:refine", "auto": true, "filed": ["https://github.com/..."]}],
   "next": "1760700300-7-42"}

host/docs/api.md has every field and the line it comes from. A field the line
does not have is left out, never null.

A cursor is the seconds of the end, the issue, and the line's place in the
order the store wrote the ends, one number across cycles and planning turns.
The last is what --after reads, so a line written after a read is listed by
the next one even when it ended in the same second as one already read, and
a program that keeps "next" and asks again neither misses a line nor reads
one twice. An old cursor, without the third number, is read as before: the
lines after it on the seconds and the issue.

Exit: 0 printed, also with nothing to list; 1 the state store did not
answer (busy), which prints nothing; 64 an argument this command does not
know, which reads nothing; 78 the instance settings are missing or
malformed, or the state store is not installed or cannot be used, which
prints nothing.
