tehas check-product: check the product checkout against the contract tehas
and pi-rukas read from it, and say what is missing.

Usage:
  tehas check-product             check the checkout, one line per check
  tehas check-product --sandbox   the same, then run the product's gates on a
                                  fresh clone in the sandbox image

The checks, on the commit origin's default branch points at, since a cycle
reads only what is committed there:
  origin    the checkout is a clone of TEHAS_REPO
  default   origin/HEAD is set, so the default branch is known locally
  agents    AGENTS.md is there
  gate      .pi/verify-cmd has a line that is not empty or a comment
  model     .pi/settings.json, when the product has one, names a model the
            instance's models.json lists
  install   what a cycle installs before it starts: the first command of
            .pi/install-cmd, else one install for each lockfile at the root
            or one directory down (bun.lock, package-lock.json, Cargo.lock
            and the others of tehas_core::install). Never a failure without
            --sandbox

--sandbox clones the checkout's origin/HEAD into $TEHAS_HOME/tmp/<name>, the
repository name of TEHAS_REPO. The clone is made as a cycle's workspace is
(tehas-cycle sandbox clone): the default branch at origin's tip, with
origin/<default branch> and origin/HEAD set, then a work branch with one
empty commit, so a gate that diffs against origin/main finds its base and a
change of nothing. In the image, as this user, it runs the install at the
root of the clone, then, in a worktree of the clone as pi-rukas makes one,
.pi/worktree-setup when there is one, the first command of
.pi/verify-cmd-full (else .pi/verify-cmd) and, when there is one, of
.pi/smoke-cmd. An install that fails, or a tool the image lacks, fails the
install check and runs no gate. All of it is removed afterwards.

It changes nothing in the product. The result is written to
$TEHAS_HOME/state/check-product.json, which tehas status reads.

Exit: 0 every check passed; 1 the sandbox could not be run; 64 a wrong
argument; 78 the instance settings are missing or malformed, or a check
failed.

Instance settings (lib/config.sh): TEHAS_REPO, required; TEHAS_WORK_REPO,
derived. --sandbox also uses PI_ENSEMBLE_IMAGE.
