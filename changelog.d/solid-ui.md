### Changes

- The front end's kit, `host/fun/kit/` (`kit 1`), now carries Solid 2 as one vendored module, `kit/vendor/solid.js` (solid-js 2.0.3, @solidjs/web 2.0.3, @solidjs/signals 2.0.3, @solidjs/html 2.0.1, MIT), with the island base, the feed store, page stores shared by the islands of a page, and shared parts. `host/docs/frontend.md` describes the split, the island contract and the Solid 2 rules.
- The plain dashboard at `/dashboard` is drawn by Solid islands on the kit (`host/fun/factory/`), one per section, with the same markup and look. The server HTML stands until each island mounts, and every island that reads a `/live/` file shares one poll of it. The times beside the issues, the queue and the list of previews show: they were empty before. The age of the host's snapshot is judged by the server's clock, as before.
- The kit's feeds can send request headers and credentials, read text, take a status such as a deliberate 404 as data, and give the last answer's status, chosen headers and the server's `Date`. The kit adds a stream source for server-sent events and NDJSON over fetch, which sends headers and connects again with a backoff, and a press for posts run inside Solid's `action()` with an optimistic value. `host/docs/frontend.md` has a section on moving a hand-written client onto them.
- A page moved onto the kit can keep what its own client did. A stream takes `end`, to stop for good on the statuses or content types it names as an `EventSource` does, carries a refused answer's body on its error (`StreamError`, as `PressError` does), takes `hidden: "live"` to connect again while the page is hidden, and takes `grow: "fixed"` and `ended`, the wait after the server ends a stream cleanly, beside `retry` and `max`. A feed's `refresh()` now returns a promise of the answer it asked for, and `put(value)` gives every reader of a feed a value the page already has, such as a press's answer, with no fetch. A stream or feed that uses none of these behaves as before.
- The byte ratchet counts the library once, on a `library solid` line of `host/fun/pages.max`, and in no page. It fails when the kit's `MANIFEST` does not match its files, on Solid 1.x names in `host/fun`, on a library import outside a `.render.js` file and the kit files that draw, and on `html` templates built from strings or with a `style=` attribute.
- The docs server sends `Cache-Control: no-cache` for every file under `/fun/` whose name holds no content hash: the theme, fonts, images and the kit's modules. Before, those had no cache header and a browser could reuse an old copy after an update.

### Adopter action

A program that builds pages on the kit copies `host/fun/kit/` whole at the tehas tag it pins, checks every file against `kit/MANIFEST` (`file <sha256> <bytes> <name>`), and does not edit it. Its render modules import Solid by a relative address to `kit/vendor/solid.js`, with no import map, and only the names `host/docs/frontend.md` lists under "Solid 2 in tehas". When it updates the pin, it copies the kit again and checks the manifest.
