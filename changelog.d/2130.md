### Changes

- The poll ends a sandbox push fault on its own. Once `state/push-fault.json`
  is ten minutes old the poll runs the sandbox's dry-run push itself, with no
  cycle spent on it: a check that passes takes the file off and the queue
  starts, one that is refused writes the fault fresh and holds starts for
  another ten minutes. A probe whose own container could not start (no docker,
  no daemon, no image named) is the host's fault and records nothing, so the
  poll asks again on its next run instead of holding on a check that never ran.
- `tehas status` prints `push      the sandbox cannot push: <git's line>
  (<login>)` while the fault stands, and `tehasbot health` fails the page with
  it, so the host says the fault without anyone reading the poll's log.

### Adopter action

None. The fix of a host that cannot push is nearly always the GitHub App's
install needing Contents read and write on the product repository; see
[Troubleshooting](/troubleshooting#the-sandbox-cannot-push).
