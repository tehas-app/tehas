### Changes

- `tehas answer <issue> <choice> --by <login> [--json]` answers the question a stopped ticket or a planning session waits on, for a person, from a program on the host such as an industry: `retry`, `retry-text` or `park` for a stop, `option:<k>`, `update`, `end` or `--text <file>` for a planning question. `--by` must be an account of `TEHAS_ALLOWED_LABELERS`, or it stops with 78. The answer is recorded in the state store with who gave it and when, and the next poll acts on it as on the same box ticked by that account. The boxes still work as before (#2782).
- `tehas answer <issue> --text - --by <login>` reads the reply in words from standard input, for a program that may not write a file on the host. It is bound to 1 MiB, as a file is, and empty input stops with 64 (#2782).
- `tehas api --json` lists the feature word `answer` in `features`: a program that manages factories of more than one release checks for it before it uses `tehas answer` (#2782).
- A retry an answer asked for is recorded with `how` `answer` in `tehas history`, the start comment and the approval record (#2782).
- The state store is at schema 24: it adds `answers`, the answers `tehas answer` gave, each bound to its question, and a cycle's `how` may say `answer` (#2782).

### Adopter action

Run `tehas update`, which migrates the store to schema 24.
