### Changes

- A pull request's checks hold the newest run of each GitHub Actions workflow and event. A newer run of the same workflow and event, scheduled or re-run, now supersedes an older one, so a commit whose workflow failed once and passed in every run since reads passing, where it read failing forever. Two workflows with a job of the same name are still both counted, so a failing one is never hidden by a passing one, and a workflow's `push` run never hides its `pull_request` run. A re-run that is queued reads as pending. The workflows come from one read of the commit's workflow runs; when that read fails, the checks are not read that poll, and an App without `actions: read` is told so: "the App cannot read workflow runs (actions: read)". A check of any other App keeps the newest run of each check suite.
