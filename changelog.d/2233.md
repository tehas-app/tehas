### Changes

- The dispatcher's poll reads `TEHAS_PLAN_TIMEOUT` and `TEHAS_PLAN_MAX_TURNS`
  strictly. Unset or empty keeps the poll's own defaults, 3600 seconds and 20
  turns (the settings load gives its own default, 7200 for the timeout, whether
  the instance sets the name to nothing or not at all). A value that is set and
  is no whole number of at least
  1, is no text this program can read, or is a timeout over 7200, now stops the
  poll with one ERROR line and exit
  78 before the lock is opened and before any call to GitHub, Docker or git.
  Before this the poll read `parse().unwrap_or(..)`: `TEHAS_PLAN_TIMEOUT=1h`
  became 3600 and `TEHAS_PLAN_MAX_TURNS=two` became 20, so a planning session
  ran the default and the instance's own words were never heard, while the
  same text fed to the settings load was refused. The load says the same words
  on a host that sets them in `instance.env`; the poll's own read is what
  stands when no load ran (exit 78, `tehas help dispatch`). The turns bound has
  no ceiling: how many turns a planning session may take stays the instance's
  to choose, within the rule's nine digits.

### Adopter action

None. An instance that set either name to something the settings load accepts
needs nothing. One that carried a value the load refused never started a poll
at all, since the load stopped it first. A poll started with no load — a shell,
or a unit that does not source `env.sh` — that carried such a value ran the
default before and now stops with 78, so that host sees a new refusal.
