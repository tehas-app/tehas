### Changes

- The state store moves to schema 30 (`tehas update` migrates it). The how word `label` is `approved`: `cycles.how` takes `approved` and no longer `label`, and every `label` in the cycles' how, the cycle history's how and the approvals' how, label and started how is rewritten. `tehas history`, `tehas export`, the approval record, `libexec/store approval-record --how` and `history-show --how`, and the MCP server's `factory_sessions` take `approved` and no longer `label`. A planning turn's first how in analytics is `approved` too.
- A question has the store's own number (schema 30): `questions.id` is given in order and never reused, the existing questions numbered in the order they were asked, and the id of the comment that asked it is kept beside it, read only by the store and the code host's side of the poll. The answers move with their questions. `id` in `tehas question --json` and `question.id` in `tehas answer --json` are that number, no longer the comment's id.
- A withdrawn question is kept with when it was withdrawn (`questions.withdrawn_at`), not deleted, and its answer stays with it. It is no longer on record and takes no answer.
- The cycle history keeps when each line was written (`cycle_history.recorded_at`, the line's end on the lines there), and a line of the v0.30 ledgers with no start time takes its end as its start. `cycle_history.signalled` is laid for the events work, 0 on every line there.
- The state store has an id of its own, 32 hex digits from the host's random source, kept in `meta` under `store`: a new store gets one when it is laid, and the step to 30 gives one to a store that has none.
- The analytics database, `state/analytics.db`, moves to schema 7 the first time it is opened after the update. The end word `pr` is `offered`: `runs.outcome` takes `offered` and no longer `pr`, and every `pr` outcome and every `label` how is rewritten. `v_versions` counts `offered` with `merged` in its share of the runs that reached a change, whose column `pr_share` is `change_share`. The stats report's `runs` count and the MCP server's `factory_stats`, `factory_sessions` and `factory_outcomes` say `offered` in place of `pr`. A file of schema 4, 5 or 6 is migrated in place; `tehas analytics copy --json` reports schema 7.

### Adopter action

Run `tehas update`, which migrates the state store to schema 30. A program that reads `how` (in `tehas history`, `tehas export` or the analytics) reads `approved` where it read `label`, and one that filtered by `label` filters by `approved`. A program that kept a question's `id` from `tehas question` or `tehas answer` as a comment id keys it as the store's number from now on: the numbers of 1.x name comments and do not match. A program that copies `state/analytics.db` pins the new schema, `user_version` 7 and `console/analytics/src/schema.pinned` of this release, and reads `offered` where it read the outcome `pr` and `change_share` where it read `v_versions.pr_share`. No old word is kept as an alias.
