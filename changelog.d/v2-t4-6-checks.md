### Changes

- The dispatcher's branch check (`TEHAS_BRANCH_CHECK`) reads the check on the branch's head through the code host port, which folds every run and commit status of that name, so a passing job of one workflow does not hide a failure of another workflow's job with the same name. A failing commit status with the check's name now holds new cycles too, as a failed check run does. A poll that checks the branch makes four reads of GitHub for it where it made one: the branch's head commit, its check runs, the workflow runs they belong to and its statuses. When the code host refuses to say the check, the poll says once each poll `WARN: the code host refused to say the checks of <branch>; the factory's account may lack a permission (host/docs/github-app.md#the-permission-to-read-the-checks)`, and the check is unreadable, never passed. That section of the GitHub App page says how to give an app made before "Actions: Read-only".
