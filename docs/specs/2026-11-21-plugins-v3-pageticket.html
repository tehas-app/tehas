Page Ticket

Start from an image, a page address, or a page's HTML. The plugin makes one standalone HTML prototype of the page. You change it by chatting with a session that knows the app's source, then hand it off. The prototype and its notes become the spec that the pi-rukas plan builds against. This copy runs on a built-in example app.

and the page

The plugin opens the address in a headless browser, waits for it to settle and saves the rendered page with its CSS, images and fonts in one file, scripts removed. A page in your browser cannot do that, so here you upload that file or use the example.

Or the page's HTML A standalone HTML file. Scripts and event handlers are removed. Example: harbour-web, home page

What the workspace opens with

Both sides are shown whole. The prototype is a real page in a frame, scaled down with CSS.

How a ticket is made

  1. 1CaptureHeadless browser at a fixed viewport saves the page as one standalone HTML file.
  2. 2PrototypeCaptured, uploaded or drafted from an image: from here every input is one HTML file.
  3. 3CompareWith an image: both are broken into components, matched, and the differences listed.
  4. 4ChatThe session knows the app's source. It edits the prototype and asks whether a shared part changes on all pages.
  5. 5Hand offPrototype and notes saved on the host, a record in the state store, a ticket that links them.
  6. 6PlanA person labels the ticket. pi-rukas plans against the markup and the notes.
