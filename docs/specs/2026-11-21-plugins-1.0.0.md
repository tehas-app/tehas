# Plugin specification 1.0.0

**Status**: 1.0.0, 2026-11-21. Stamped by the owner's decision: Floorplan,
the spec interview and the page ticket are the three plugins that ship first,
and these files are the whole specification they ship with. Nothing is built
beyond what each file says.

## The files

One specification, read in this order. A later file changes an earlier one
where it says so, in its "Changes to" tables.

| File | What it holds |
| --- | --- |
| `2026-11-21-plugins.md` | v1: guarantees, settings, the manifest, runs, commands, licences, Floorplan |
| `2026-11-21-plugins-security.md` | v1: the container, the build, `/out` and `/state`, the model socket, grants |
| `2026-11-21-plugins-web.md` | v1: the edge, the gate, the sign-in, the browser's policy, the kit, actions |
| `2026-11-21-plugins-hooks.md` | v1: `after:work` |
| `2026-11-21-plugins-v2.md` | v2: what it adds, the rules it keeps, the spec interview plugin |

specification: the specification's version is the number on this page.

## Revisions

A change of scope after 1.0.0 is a revision: a pull request that changes the
files above and adds a row here. A new capability or surface moves the minor
number (1.1.0). A correction that changes no behaviour moves the patch number
(1.0.1). The manual, `host/docs/plugins.md`, says which revision a release
implements.

| Revision | Date | What changed |
| --- | --- | --- |
| 1.0.0 | 2026-11-21 | The first stamp: v1, v2 and v3 as one specification |
| 1.0.1 | 2026-11-21 | Corrections to v2 after an independent review against v1 and the chat hosts' code. A service keeps `--network none` and the gate reaches it over a unix socket. `asks` allows 32. v1's "refused as v2" rows are lifted for what v2 adds, `view` and `views` are exclusive, and `kind` is optional without a build.
