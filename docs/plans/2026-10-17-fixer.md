**Goal:** a loop, `tehasbot fix`, that decides on parked issues (retry, retry with a change, leave for a person) and may apply `tehas:ready` through its own account, within limits the dispatcher enforces.

**Architecture:** the shape of the improvement loop. The script gathers inputs, a model in the sandbox reads them read-only and writes one decisions file, the script checks it against a fixed shape and against hard rules, and makes every GitHub call with the fixer's own token. The dispatcher accepts a `tehas:ready` from `TEHAS_FIXER_LOGIN` only on an issue a person approved before, with the body unchanged, under a per-issue cap. Shared rules live in `lib/fixer.sh`.

**Tech stack:** bash, jq, gh, docker (Pi in the sandbox image), systemd user units.

**Spec:** issue #294 (parts 1 of 4: settings, account, dispatcher grant, parked issues, precedent). Parts 2 to 4 (stale pull requests, ordering, planning answers) get their own plans.

## Global constraints

- Platform files name no product and no host (rule 1). Examples use tehas-tehas.
- A command fails closed with exit 78 before it calls GitHub, Docker or git (rule 2).
- `lib/config.sh` stays free of side effects (rule 3).
- `libexec/work`'s mounts and environment do not change (rule 4). The fixer's guidance reaches a cycle only through `retry-context.md` in the images directory that is already mounted where the instance gives images or files.
- Authorisation is who applied the label (rule 5). The fixer is its own account, never the bot, never in `TEHAS_ALLOWED_LABELERS`.
- Tests need bash, git, jq and shellcheck only (rule 6).
- No token on a command line (rule 10): the fixer's token reaches gh as `GH_TOKEN` in the environment of that one call.
- Defaults: `TEHAS_FIXER_MAX_RETRIES` 2; at most 5 actions a run; one per issue.

## Decisions made here (my calls, said in the pull request)

- The fixer's token is `TEHAS_FIXER_TOKEN` in `~/.config/tehas/env`, kept by `tehas_load` like `TEHAS_MODEL_KEY_*` and refused in `instance.env`. A missing token stops `tehasbot fix` with 78; the dispatcher does not need it.
- `tehas:fixer-escalated` comes off when a person applies `tehas:ready` (the start drops it) or takes it off by hand. The fixer does not watch for comments.
- Parks after a provider outage do not count for the same-reason rule: the retry cap bounds them.
- "Retry with a change" is offered only where the instance gives a cycle images or files (`TEHAS_WORK_IMAGES=1` or `TEHAS_WORK_FILES=1`); elsewhere the guidance would reach no one.

## Interfaces

Approval record, `state/cycles/<n>.approved.json`, for a fixer start:

```json
{"at": "...", "by": "<fixer login>", "how": "fixer", "body_sha256": "...", "links": [...],
 "rests_on": {"at": "...", "by": "<person>", "how": "label|retry-tick|outage-retry", "body_sha256": "..."},
 "fixer_starts": 1,
 "retry_context": [{"source": "fixer:<comment id>", "by": "<fixer login>", "at": "...", "text": "..."}]}
```

`rests_on` is the record itself (its four fields) when the earlier record's `by` is a person, else the earlier record's `rests_on`. `fixer_starts` is the earlier record's count plus one when the earlier record is a fixer's, else 1.

Cycle history, `state/cycles/<n>.history.jsonl`, one line per ended cycle:

```json
{"at": "...", "started": 0, "rc": 0, "status": "...", "step": "...", "cap": "...", "park_reason": "...",
 "failure_kind": "...", "failure_cause": "...", "provider": false, "parked": true, "pr": "...", "by": "...", "how": "..."}
```

Park signature: `[.step, .cap, .park_reason, .failure_kind, .failure_cause] | join("|")`.

Fixer comment marker: `<!-- tehas:fixer issue=<n> action=<retry|change|person> -->`.

Decisions file the model writes, `out/decisions.json`:

```json
{"decisions": [{"issue": 12, "action": "retry|change|person", "why": "...", "change": "...",
  "note": "...", "precedent": [{"issue": 40, "comment": 123456}]}]}
```

## Review focus

- A fixer label on an issue whose last record is the fixer's own and whose `rests_on` is missing or malformed: refused.
- An approval record that is a link: refused.
- A decisions file that is a link, over 1 MB, or not JSON: the run fails, nothing is applied.
- Text in a decision that mentions an account or holds an HTML comment: defused before it is posted.
- A label applied by the fixer while a cycle runs: waits like any other.
