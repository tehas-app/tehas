# Read-only MCP server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only MCP server that serves a factory's public `/live/` data to outside agents, behind a list of API keys.

**Architecture:** A third member of the Cargo workspace in `console/`, `console/mcp`, built static (musl) by `install.sh` and installed as `~/tehas/libexec/tehas-mcp`. `tehasbot mcp serve` (bash, `libexec/mcp`) checks the settings and runs the binary in a locked-down container with only `~/tehas/live` mounted read-only; `tehas-mcp.service` runs that command. The binary is pure functions (keys, allowlisted tools, JSON-RPC) behind a small HTTP loop.

**Tech Stack:** Rust 2021 (`serde_json`, `tiny_http`, `sha2`), bash, systemd user unit, Docker.

**Spec:** `docs/specs/2026-10-20-mcp.md`. Read it first. For the protocol, read the MCP 2026-07-28 text itself: <https://modelcontextprotocol.io/specification/2026-07-28> (pages `basic/transports/streamable-http`, `basic/versioning`, `server/discover`, `server/tools`, and the backward-compatibility section of `basic/versioning`).

## Global Constraints

- MCP revision `2026-07-28`, plus the `2025-11-25` handshake fallback. Nothing older.
- Tools only, read only. No resources, prompts, subscriptions, tasks.
- Input: only the directory given as `--live`, read only. No other path, no network call.
- Every tool result carries `"api": 1`; fields only added within version 1; a field without a value is left out.
- `TEHAS_MCP` (`0`/unset off, `1` on) and `TEHAS_MCP_KEYS` (space-separated) live in `~/.config/tehas/env`. Each key: at least 32 characters of `A-Za-z0-9_-`. On with no keys or a bad key: exit 78, a line naming the setting, never the key.
- Auth: `Authorization: Bearer <key>`, constant-time compare; otherwise 401, `WWW-Authenticate: Bearer`, empty body.
- A key never appears in a log, an error, a command line or a response. The log names a key by the first 8 hex characters of its sha256.
- Request bodies over 65536 bytes: 413.
- Port 8082 on `${TEHAS_HOST_ADDR:-127.0.0.1}`.
- `AGENTS.md` rules: tests first; shell tests need only bash, git, jq, shellcheck; Rust `cargo fmt`, `cargo clippy` clean, no `unsafe`; platform files name no product or host; the manual changes in the same commit as the behaviour; `scripts/verify.sh` before saying done.

## Review Focus

1. A live file mid-write or missing (the dispatcher writes `x.new` then renames): the tool returns a tool error naming the file, the server keeps serving.
2. `running.json` naming a console file that is not `console-<digits>.txt` for that cycle (`../`, absolute, another issue): never opened.
3. A proxy in front sends `Authorization: bearer <key>` (lower-case scheme) or extra spaces: lower-case scheme is accepted, any other difference is 401.
4. An agent that sends a 2025-11-25 `initialize` and then calls tools with no `_meta` version: served, not refused.
5. `TEHAS_MCP_KEYS` with a trailing newline or tabs from an env file: split on any whitespace, not just single spaces.

### Task 3: The protocol

**Files:**
- Create: `console/mcp/src/rpc.rs`, `console/mcp/tests/rpc.rs`

**Interfaces:**
- Consumes: `tools::list`, `tools::call`, `keys::Keys::check`.
- Produces: `pub struct Request<'a> { pub method: &'a str, pub headers: Vec<(String, String)>, pub body: &'a [u8] }`; `pub struct Response { pub status: u16, pub headers: Vec<(String, String)>, pub body: Vec<u8>, pub key: Option<String> }`; `pub fn handle(req: &Request, keys: &Keys, live: &Path, server_version: &str) -> Response`. `key` is the fingerprint for the access log.

Rules (from the 2026-07-28 text; check every name against it):
- Not `POST`: 405. No or bad key: 401, `WWW-Authenticate: Bearer`, empty body, before the body is parsed. Body over 65536 bytes: 413. Not JSON-RPC 2.0: JSON-RPC error `-32600`.
- A request carries `params._meta["io.modelcontextprotocol/protocolVersion"]`. `2026-07-28`: check `MCP-Protocol-Version`, `Mcp-Method` and, for `tools/call`, `Mcp-Name` headers against the body; a mismatch is HTTP 400 with error `-32020`. Another value: error `-32022` with the supported versions `["2026-07-28", "2025-11-25"]`.
- No `_meta` version: the 2025-11-25 path. `initialize` answers `protocolVersion: "2025-11-25"`, `capabilities: {tools: {}}`, `serverInfo: {name: "tehas", version}`, and sets no session header; `notifications/initialized` and any notification: 202, empty body; `ping`: `{}`; `tools/list`, `tools/call` as below.
- `server/discover`: supported versions, capabilities `{tools: {}}`, server info.
- `tools/list`: `{resultType: "complete", tools: tools::list(), ttlMs: 30000, cacheScope: "private"}`.
- `tools/call`: `Ok(v)` gives `{resultType: "complete", structuredContent: v, content: [{type: "text", text: <v as JSON>}]}`; `File`, `BadArgs` give the same shape with `isError: true` and a text that names the file or argument; `Unknown` is JSON-RPC error `-32602`.
- Results carry `_meta["io.modelcontextprotocol/serverInfo"]` on the 2026-07-28 path. `Content-Type: application/json` on every JSON body.

- [ ] **Step 1: Write the failing tests** in `tests/rpc.rs`, one per rule above, with the Task 2 fixtures and two test keys; plus: a 2025-11-25 sequence `initialize`, `notifications/initialized` (202), `tools/list`, `tools/call factory_status` all succeed without `_meta`; a 2026-07-28 `tools/call` whose `Mcp-Name` differs from `params.name` is 400; a wrong key's response body is empty and its headers carry no key; `server/discover` lists both versions.
- [ ] **Step 2: Run** `cargo test --manifest-path console/Cargo.toml -p mcp --test rpc` — fails.
- [ ] **Step 3: Implement** `handle` in `rpc.rs`. Header names compared case-insensitively.
- [ ] **Step 4: Run** — passes; clippy clean.
- [ ] **Step 5: Commit** `git commit -m "The MCP server answers 2026-07-28 and the 2025-11-25 handshake"`
