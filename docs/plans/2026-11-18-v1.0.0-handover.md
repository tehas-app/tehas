### Finish beta.3

1. `scripts/tag-release.sh --major --pre beta`. It collects the changelog
   fragments, opens the pull request `changelog-v1.0.0-beta.3` and exits 2.
   Without `--major` it would tag v0.32.1-beta.1. On a small host,
   `--no-verify` skips its local gate; CI gates the changelog pull request
   and main anyway.
2. Merge that pull request when its CI is green.
3. Run the script again. It tags v1.0.0-beta.3 and pushes the tag.
4. The release run waits for the `release` environment. Approve it:
   `gh api -X POST repos/tehas-app/tehas/actions/runs/<run>/pending_deployments -F "environment_ids[]=27505289849" -f state=approved -f comment=beta.3`.
5. Rewrite its notes as for beta.1 and beta.2: the Changes and Adopter
   action lines in the Unreleased section of `CHANGELOG.md` at the tag that
   were not there at v1.0.0-beta.2, then the section "Updating from 0.30.x
   or 0.32.x" the other two carry. `gh release edit <tag> --notes-file`.

## industry.tehas

The industry host is `tehas-industry` (Tailscale SSH as root; see
trail-openers/tehas-industry-infra, `docs/operations.md`). It runs industry
v0.36.0 and the factories nessie and pi-rukas, both on tehas v0.30.6.

- trail-openers/tehas-industry-infra#31 is merged: both factories' `tag`
  is v0.32.0 in that repository's main. Neither factory runs it yet.
- `industry factory upgrade nessie --no-drain` stopped with 78 and
  switched nothing: industry writes `TEHAS_TICKET_CONCURRENCY` into the
  factory's `instance.env`, and tehas 0.31 and later refuse it (renamed
  `TEHAS_MAX_CYCLES`). It also writes `TEHAS_INDUSTRY_VERSION` (renamed
  `TEHAS_MANAGER_VERSION`).
- The fix is tehas-app/tehas-industry#1405, "speak tehas 1.0's renamed
  names", opened 2026-11-17 and not merged. After it is merged and
  released: `ssh root@tehas-industry industry upgrade`, then
  `industry factory upgrade nessie` (to v0.32.0), then an infra pull
  request that moves the tag to v1.0.0-beta.3 and another upgrade. A 0.30.6
  factory cannot name a beta, so the v0.32.0 step is needed.
- nessie is undrained and working: 3 cycles ran through the attempt.
- The pi-rukas factory is down, and was before this work: `industry status`
  reads "no instance.env in /home/tehas/.config/tehas", exit 78, last
  report 44 h before. The documented repair is
  `ssh root@tehas-industry industry factory create pi-rukas`. Not run;
  the owner decides.
- The update docs should name this as a known limit: a manager that writes
  0.30 names into a factory's settings stops the update with 78.
